How it works

Knowledge that knows when it's wrong.

Your repository keeps what your team has learned in .knowledge/, next to the code it is about. A record says why, and it says what must stay true in the code. When a change makes it untrue, the agent making the change and the pull request both say so.

Plain Markdown, in git, reviewed in the pull request like code. Anyone can read it with nothing installed.

1Write

Written in the change that makes it true.

When an engineer or an agent decides something the code can't say, it writes a record in the same branch. In Claude Code the agent uses DocBrain's MCP tool, or the docbrain record command where MCP is blocked.

Every check is tested against the code before the file is written. A record that doesn't hold is refused, so a record never starts out broken.

2Read

Read at the moment of change.

Before Claude Code edits a file, the DocBrain hook shows it the records that apply. After the edit, it checks them again.

Here the agent compiles each rule once to save CPU and drops the budget along the way. The record turns broken before anything is committed, and the agent knows why the budget was there.

The hook needs only the CLI, so it works where MCP is blocked.

3Check

Checked on every pull request.

A CI job runs the same check on the change and flags the file in the pull request, with the record's reason next to it.

It blames a change only for what that change broke. A record that was already broken on the main branch is not this change's finding.

It warns by default. Blocking is your repository's choice: add --fail-on broken and the same job fails.

4Answer

Answered across every repository.

DocBrain's server reads each repository's records from its default branch, so a question asked anywhere can be answered from them.

  • It reads, and never writes. No pushes and no bot pull requests. Git stays the only writer.
  • Ask answers from them the way it answers from every other source it reads.
  • Agents reach them through MCP with docbrain_context, under each repository's own read access.
